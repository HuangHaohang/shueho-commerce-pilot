# 全公司使用的容量与可用性门槛

Commerce Pilot 是基于 OpenAI 开源 Codex Harness 的浏览器应用。以下是面向
100 多名员工的工程验收方案，不是生产容量承诺。实现和实测结果见
[2026-09-12 验证报告](../reports/2026-09-12-company-readiness.md)。

## 工作负载与验收口径

暂按 100 人同时在线、20–30 个 AI 任务并发设计验证；真实峰值仍需业务方确认。
员工数、HTTP 并发、原生 Turn 并发、子 Agent 数、图片任务数是不同指标。
现有 Enterprise 合同和用户/工作区配额继续生效，本次没有提高任何真实客户额度。

| 场景 | 验收目标 | 当前证据边界 |
| --- | --- | --- |
| 100 名独立用户，各保持 SSE 并周期读取 4 类业务接口 | 每用户/接口都有覆盖；意外错误 0；P95 ≤1500 ms；每条 SSE 收到 connected 帧 | 3687次零错误，整体P95 1434.9ms，100/100 SSE；热点接口仍超过1500ms |
| 100 用户数据库访问 | 真实 RLS、零归属错误、事务等待有界、短断连不终止 Web | 3 轮基线/候选共12000事务、0错误；78项隔离检查 |
| 断网、SSE 重连和历史读取停滞 | 有界只读恢复；保留原生终态；不重复提交任务 | 真浏览器受控故障、20条DB连接终止、Web进程强停均恢复；不含实际上游模型 |
| 20–30 个混合 AI 任务 | 测量提交确认、首个有效事件、原生终态、费用及不确定结果 | 需要有效 Provider、审批后的真实调用和实际业务样本 |
| 企业可用性 | 建议以99.9%月可用性作为待确认目标，定义告警与恢复责任 | 本次没有生产持续运行或灾备演练证据 |

1500 ms 是短业务读取的验收门槛，不适用于图片生成和复杂研究的完成时间。
生成任务分别记录排队/提交、首次可见进度、首个可用产物和 Harness 完成时间；
不能用 loading 动画当作有效进度，也不能用收到 HTTP 200 当作生成成功。

## 本次已实现的保护

- App Server 并发冷启动共享完整握手；旧进程退出不能清掉新进程请求。
- 每条 SSE 最多积压1 MiB；持续背压30秒断开该订阅，其他用户和原生任务继续。
- 重连合并只读恢复；整轮与响应体读取有15秒上限。切换任务取消旧读请求，
  不把网络超时变成 Harness 失败，不重放模型或供应商调用。
- RLS 初始化由4次SQL往返合并为1次。回滚失败销毁连接，数据库短故障后的角色
  校验允许重新执行；不缓存业务权限、不自动重试业务SQL。
- 模型目录请求合并、正文有界、读超时覆盖正文。401/403撤销缓存；临时故障
  仅在期限内允许普通读取复用旧目录，强制刷新保留失败。
- 报告缺少依据、置信/决策矛盾或加权错误时标“待复核”，保留正文与证据。
  这是确定性一致性检查，不能替代领域专家评审或真实模型内容质量评测。

## 数据库连接预算

`COMMERCE_DATABASE_POOL_MAX` 是每个 Web/worker **进程**的上限，默认生产20、
开发5，允许1–100。`COMMERCE_DATABASE_CONNECT_TIMEOUT_MS` 默认5000 ms，允许
100–60000 ms。不要把单进程上限直接设置成员工总数。

预算公式：所有 Web 副本池上限 + 所有 worker 池上限 + 外部数据服务连接 +
管理/迁移/监控预留 < PostgreSQL 可用连接数。增加副本前先核算总量；迁移角色
不能用于长驻业务进程。Pool 等待超时不代表供应商未执行，不能因此重试付费操作。

## 办公网出口与边缘保护

`deploy/production-web/edge.conf` 按方法分开计数：GET/HEAD 为150 r/s、burst300；
写请求保留30 r/s、burst100。同一办公网络的多人读取不再消耗写请求额度。
只有公开 `/_next/static/` 构建资源免请求率限制，并拒绝写方法。

每IP最多600个活动连接、全server最多800个，连接超限统一429；它们是边缘保护
上限，不是已经证明的容量。SSE和API继续禁用代理缓冲及上游自动重放；只有
公开静态资源开启缓冲。内部API仍404，上传大小例外、可信代理地址和Gateway
内部网络边界保持不变。不得拿可伪造的浏览器cookie或租户header作为限流身份。

## 高可用部署边界

单机 `restart: unless-stopped` 不能覆盖宿主机或磁盘故障。全公司开放前，需要
实际演练 Web/Gateway 重启、数据库连接中断、上游限流/不可用、SSE断线及恢复。
只读页可水平扩展，但要统筹数据库连接、统一认证配置和正确租户Gateway路由。

一个租户的 Codex `CODEX_HOME`/SQLite历史不能被两个活动Gateway同时共享写入。
如需主备切换，应先完成旧实例隔离和持久卷单写者切换，再启动新实例并按原生
历史读回任务状态；不得新建第二个任务冒充恢复，也不得重发结果不确定的付费调用。
本次没有实现跨宿主机主备控制器或验证RTO/RPO，不能称为完整高可用部署。

监控至少区分：短API延迟/5xx/429、连接池等待、Gateway/MCP readiness、SSE重连、
活动Turn与配额、事件outbox/dead-letter、Provider认证/限流、产物到原生终态的延迟。
不采集提示词、正文、工具参数/结果、凭据或客户PII作为指标标签。

## 开放给全公司前

1. 修复运行配置：有效Provider凭据、正确服务地址、租户固定配置。当前本地旧库
   的未归属历史任务必须由用户指定企业/工作区，不能跳过迁移040或随意归属。
2. 在专用环境完成100用户真实认证HTTP/SSE读取压测；保留失败基线。详见
   [压测说明](../../scripts/load-test/README.md)，目录stub明确拒绝模型执行。
3. 获得真实调用预算后，用公司实际文案/商品事实/图片参考/研究问题评测质量、
   时延和正确终态。覆盖资料不足、错误证据、编辑连续性、取消与不确定返回。
4. 在目标生产网络和机器上做持续负载与故障恢复验证，再分批开放10→30→100人。
   每阶段观察错误、限流、等待和用户反馈，不以本机数据库微基准代替发布验收。
